<objective>
The interface for role preview as approved in [30-CONTEXT.md](30-CONTEXT.md):
the picker in the toolbar panel, the read-only banner, exit.
</objective>

## Tasks

1. **Picker in the toolbar panel.** A visible "Preview as" label, a native
   `<select>` of the site's roles and a "Preview" button. Choosing a role does
   nothing by itself. Preview first flushes any pending autosave and waits for
   it; if the save fails, it stays put and says so. Then it navigates to the
   current admin URL with `maestro_preview=<role>` and the nonce, without
   `maestro_edit`. Hidden for super admins, with a one-line explanation.
2. **Banner.** Server-rendered at the top of the page while previewing, outside
   the editor script: "Previewing menu as Editor — read-only", the same native
   picker with a Preview button (a plain GET form carrying the nonce), and an
   "Exit preview" link back to the same page in edit mode. It uses the
   viewer's real capabilities, so it is there even when Editor cannot reach
   Maestro. A short note says the preview approximates the role and lists what
   can differ.
3. **Refusals.** A crafted or stale request (bad nonce, unknown role, super
   admin) shows a notice saying why and renders the ordinary menu.
4. **Admin bar.** While previewing, the toolbar node reads "Exit preview".
5. **e2e** (`role-preview.spec.ts`): entering from edit mode shows the banner
   and an Editor-shaped menu (no Plugins, no Settings), a Maestro rule hiding
   Posts from Editor applies in the preview, the page itself still loads as
   admin, nothing posts to the config route, Exit restores the full menu
   with rules unchanged, a request without the nonce is refused, and a
   pending rename is saved before entry.
