**The three hardcoded values** (verified 2026-08-10 against `main`):

| Location | Rule | Role |
|---|---|---|
| `maestro.css:22` | `width: 160px !important` | unfold backstop on `#adminmenu`/`#adminmenuwrap`/`#adminmenuback` |
| `maestro.css:28` | `margin-left: 160px !important` | matching offset on `#wpcontent`/`#wpfooter` |
| `maestro.css:523` | `left: 160px` | the toolbar's left edge — "clears the admin menu column" |

`maestro.css:485`'s `max-height: 160px` is an unrelated results-list bound. Do
NOT touch it — it is the same number by coincidence, which is exactly the trap.

**Both layers enforce the unfold**, and both must stay in step: `forceUnfold()`
in `maestro.js` (~L197) strips the classes and re-strips via `MutationObserver`,
and the CSS above is the defensive backstop for a frame where the class survives.

**The collapse control today:** a capture-phase listener calling
`preventDefault()` + `stopImmediatePropagation()`. Phase 25's derived-locked
checkbox is the model for the replacement — `aria-disabled` plus a programmatic
reason, not native `disabled`, so the control stays reachable and can explain
itself to assistive tech instead of vanishing from the tab order.
