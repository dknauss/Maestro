<interfaces>
<!-- Contracts the executor builds on. Use directly — no exploration needed. -->

**This is the first GLOBAL setting in a plugin built entirely from per-item
overrides.** Everything in the toolbar today acts on the selected item; width
acts on the whole menu and persists for every admin user. The control needs to
read as global rather than as another property of whatever row is selected, or
people will expect it to reset with Reset Item.

**Reset semantics need deciding with it:** Reset Item is per-item and must NOT
clear the width. Reset All plausibly should — it means "back to WordPress
defaults", and a 240px menu is not a WordPress default. Whichever is chosen,
assert it; this is exactly the kind of interaction that gets discovered by a user.

**Live preview is nearly free and worth a lot.** The width is a CSS custom
property after 28-01, so the control can set it on input and the menu resizes
under the cursor. A width picker that requires a save to see the result is a
worse product for no saved effort.

**Toolbar geometry follows.** `.maestro-toolbar` is `left: <width>` after 28-01 —
it must track a live change too, or the toolbar detaches from the menu column
mid-drag.
</interfaces>

  <action>
    **PLACEMENT ANSWERED 2026-08-10 — see `.planning/DECISION-settings-surface.md`.**
    The width field lives in a **Settings modal**, opened from a new icon in the
    toolbar's right zone. This phase builds that modal shell if Phase 27 has not
    already; the shell is shared.

    **With a deliberate exception this task must honour:** width should ALSO be
    directly draggable at the menu edge. 28-01 makes the width a CSS custom
    property, so live preview is nearly free, and dragging the thing you are
    resizing is more in-place than any field. The modal field is the precise and
    accessible path; the drag is the discoverable one. **Neither alone is
    sufficient** — drag-only is inaccessible, field-only is a settings screen in
    a costume.

    Remaining for this task:

    Decide also:
    - slider, numeric input, or both (a slider alone is imprecise; a number alone
      loses the live-drag feel that makes this pleasant)
    - whether Reset All clears the width
    - what the control shows when no width is stored — "160" or "Default"; the
      distinction matters because the sparse contract means "unset" and "160" are
      genuinely different stored states
  </action>
