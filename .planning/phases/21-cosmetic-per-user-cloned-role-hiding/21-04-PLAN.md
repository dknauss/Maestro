<objective>
Surface the per-user axes in the editor: model exposure, two new popover sections,
an async user picker, and the save payload.

Purpose: 21-01..03 make per-user hiding real on the server, but unreachable. This plan
is where it becomes a feature. The lockstep discipline Phase 20 required applies again —
server seam, editor model, and client payload must agree on the axes or a round-trip
save silently drops a rule the user just made.
Output: a popover with four independent target groups (role/user × item/sub-item), an
async picker that scales past a few hundred users, and a payload that round-trips.
</objective>

<task type="auto" tdd="true">
  <name>Task 3: Popover user sections, async picker, and payload</name>
  <files>assets/maestro.js, assets/maestro.css, tests/js/maestro-logic.test.js, TESTING.md</files>
  <behavior>
    - The visibility popover shows two user-target sections alongside the two role groups;
      the sub-item section appears only on parents with children (same rule as the role group).
    - Typing in a section queries `wp/v2/users?search=` debounced, and shows results to pick from.
    - Picked users render as removable chips; removing the last one clears the axis.
    - Targeting your own account renders an inline caution without blocking the action.
    - buildConfig() emits `hidden_users` / `child_hidden_users` matching 21-01's schema.
    - A save → reload round-trip preserves every rule exactly (the lockstep guarantee).
    - Toggling a user target never mutates any role axis, and vice versa.
  </behavior>
  <action>
    Follow Phase 20's structure: it factored the two role groups through one shared
    `buildRoleGroup()` closure keyed by getSet()/setSet() accessors. Build the two user
    sections through one equivalent shared closure for the same reason — four hand-rolled
    groups is where the "toggling one group edits another's model field" class of bug comes from.

    Debounce the search and abort in-flight requests when the query changes, or a fast typist
    gets results for a stale prefix. Handle the empty-results and request-failure states
    explicitly — a picker that silently shows nothing is indistinguishable from a broken one.

    Accessibility is not optional here and is cheaper to do now than to retrofit: the search
    field needs a programmatic label, the results list needs to be reachable and operable by
    keyboard, and the chips need accessible remove controls. Phase 20 shipped an a11y defect
    of exactly this shape (S1, popover groups lacking programmatic names) that had to be fixed
    at the release gate — do not re-run that. Match the focus-ring and token conventions
    Phase 23 established.

    TDD where the logic is testable; TESTING.md counts updated in the same commit.
  </action>
