<objective>
Widen the single resolution seam so a per-user rule hides a row, and refactor the
override-list resolver so the qualified-key/v2-gate logic serves both axes from
one implementation.

Purpose: the feasibility note's whole cosmetic-safety argument rests on there being
ONE drop path and ONE audit point (§2). Adding a parallel copy of
`resolved_hidden_roles()` for users would create a second place for the Axis-1/Axis-2
and v2-gate rules to drift — which is precisely the defect class already logged in
`todos/pending/2026-08-02-editor-model-replay-axis2-drift.md`. This plan makes the
gate logic field-parameterized instead, so the user axis inherits every guard the
role axis has, for free and permanently.
Output: a widened boolean seam, one shared resolver, one shared union helper, and
integration proof that a per-user hide drops a row while the role axes are untouched.
</objective>

`resolved_hidden_roles()` currently encodes THREE rules that the user axis must
inherit identically (this is why it is generalized rather than duplicated):
1. qualified `parent>child` lookup first, when `$parent_slug !== null`
2. the schema-v2 gate: a bare key that also names a rendered top-level row resolves
   to nothing for a submenu, unless `$this->config->is_legacy_bare_key_schema()`
   — this is the v1.4.1 fix from PR #115; a divergent copy would reintroduce that bug
3. the Axis-1 `$norm_skip` ambiguity guard

From includes/class-cascade.php:
```php
public static function effective_hidden_roles(
    array $child_hidden_roles, array $parent_child_hidden_roles       // ~L49
); // pure, unconditional list union — no flag, no capability call
```

Locked decisions:
- Seam shape (§2): `hidden = (hidden_roles ∩ user.roles) OR (hidden_users ∩ {user.ID})`,
  built so `OR (hidden_profiles ∩ user.profiles)` slots in later untouched.
- Ride the existing `Slug::normalize()` lookup. Do NOT add a second resolve mechanism.
- Invariants (§4), all three unchanged from the shipped role axis: intersect-against-live
  (nothing is written to the user), union-precedence (any match hides; no rule force-shows),
  non-destructive.
