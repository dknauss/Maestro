<objective>
Build ROLE-02's storage contract: the `hidden_users` and `child_hidden_users`
axes in `Config::sanitize()`, bounded and sparse, mirroring the shipped
`hidden_roles` / `child_hidden_roles` blocks shape-for-shape.

Purpose: every later plan in this phase (resolver, seam, editor model, client
payload) reads and writes these two keys. Landing the storage contract first,
unit-tested, means the rest of the phase builds against a fixed shape.
Output: a sanitize() that round-trips both user axes under the same caps and
sparseness rules as the role axes, with the role axes provably unchanged.
No replay-engine and no editor wiring in this plan.
</objective>

```php
const MAX_ITEMS = 200;          // ~L54
const MAX_HIDDEN_ROLES = 50;    // ~L93

// The two blocks to mirror, inside the sanitize() items loop:
//   hidden_roles        ~L308-318  (any key shape)
//   child_hidden_roles  ~L326-336  (guarded by `! $is_qualified` — top-level only)
public function sanitize( array $raw ): array;
```

The existing role blocks do exactly this, and the user blocks must match it:
1. guard on `! empty( $item[ $key ] ) && is_array( $item[ $key ] )`
2. `array_values( array_intersect( <sanitized member list>, <valid member list> ) )`
3. truncate to the MAX_* cap via `array_slice`
4. assign to `$entry[ $key ]` ONLY when non-empty (sparseness)

Locked decisions (21-CONTEXT.md + feasibility note §7):
- Storage is the inline parallel axis `items[slug].hidden_users` — a list of user IDs.
  NO separate top-level map (§5b explicitly rejected).
- `child_hidden_users` is the per-user analog of `child_hidden_roles`: parent-only,
  hides all live children for the targeted users while the parent row stays visible.
- Sparse contract throughout: reset = delete the key, never store an empty list.

<task type="auto" tdd="true">
  <name>Task 1: MAX_HIDDEN_USERS bound + hidden_users sanitize block</name>
  <files>includes/class-config.php, tests/unit/ConfigSanitizeTest.php, TESTING.md</files>
  <behavior>
    - A `hidden_users` list of valid user IDs survives sanitize() on a bare top-level key.
    - It also survives on a QUALIFIED `parent>child` submenu key (unlike child_hidden_users,
      the item-level axis is valid at both scopes — same as hidden_roles).
    - Members are coerced to positive integers; non-numeric, zero, and negative entries are dropped.
    - IDs not belonging to a live user are dropped (intersect-against-live, mirroring the
      role axis's array_intersect against valid roles).
    - More than MAX_HIDDEN_USERS (50) IDs truncates to the first 50.
    - An empty or all-invalid list produces NO `hidden_users` key on the entry (sparse).
    - Duplicate IDs collapse to one.
  </behavior>
  <action>
    Add `const MAX_HIDDEN_USERS = 50;` beside MAX_HIDDEN_ROLES (~L93) with a doc comment
    matching its neighbour's rationale. Add the `hidden_users` block to the sanitize()
    items loop immediately after the `hidden_roles` block (~L318) so the two axes read
    adjacently.

    IMPORTANT — the valid-ID lookup is the one place this differs from the role axis, and
    it is a performance seam: do NOT call `get_users()` inside the per-item loop. Resolve
    the valid-ID set ONCE before the loop (lazily — only if at least one item actually
    carries a user axis, so a role-only config pays nothing) and reuse it for every item.
    `get_users( array( 'fields' => 'ID' ) )` is the feasibility note's suggested source;
    the executor may use a narrower query if it keeps the same semantics. Cast the result
    to ints for a strict intersect.

    TDD: write the failing ConfigSanitizeTest cases first (RED in working tree), then
    implement to green. Per CLAUDE.md's test-blocking gate, commit test + impl as ONE
    green commit. Update the TESTING.md line-5 unit count/assertions in the SAME commit.
  </action>
  <verify>
    <automated>composer test:unit -- --filter ConfigSanitizeTest</automated>
  </verify>
  <done>hidden_users round-trips at both key scopes under cap + sparseness; invalid and non-live IDs dropped; get_users() resolved once per sanitize() call, not per item; unit green; TESTING.md updated.</done>
</task>
