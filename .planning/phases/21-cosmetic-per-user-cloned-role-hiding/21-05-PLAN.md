  <name>Task 1: End-to-end proof in a real sidebar</name>
  <files>tests/e2e/hidden-users.spec.ts, TESTING.md</files>
  <behavior>
    - Admin targets a user on the item axis; in that user's OWN authenticated session the
      row is absent, while an untargeted user still sees it.
    - Admin targets a user on the sub-item axis; the parent row stays VISIBLE in the
      targeted user's session while its children are gone — the observable effect that
      distinguishes a real cascade from an inert one.
    - The targeted user can still load the hidden page by direct URL (the escape hatch,
      proven in the browser and not only in PHPUnit).
    - Removing the rule restores the rows.
  </behavior>
  <action>

    task — a spec that only checks the admin's own editor view would pass on an inert
    implementation, which is exactly the Phase 20 trap.

    Include the direct-URL check in the browser. It is the user-visible face of the
    cosmetic-only promise, and a browser-level assertion catches a whole class of
    regression (a redirect, a die(), an over-eager guard) that a capability assertion
    in PHPUnit cannot see.

    Update TESTING.md's e2e description and counts in the same commit.
  </action>

  </verify>
