<objective>
Recapture the directory screenshots that Phase 21 made stale.

Purpose: screenshot 3 is the visibility picker. It currently shows two role
groups; the shipping UI has four. A directory listing that shows an older UI
than the plugin delivers is the most-seen inaccuracy a release can ship —
it is the first thing a prospective user looks at.
Output: accurate directory assets.

**`autonomous: false`** — someone has to look at the images.
</objective>

<interfaces>
<!-- Contracts the executor builds on. Use directly — no exploration needed. -->

Captures are `MAESTRO_CAPTURE`-gated so a normal e2e run never overwrites
committed PNGs (that gating exists because Phase 07 captures used to churn on
every run). `npm run screenshots` sets the flag and runs the capture specs.

The v1.4.0 release recaptured 1–6 plus the per-scheme editor surfaces. Its
standing lesson, learned the hard way: **do not rely on a per-milestone assets
phase to notice staleness** — diff the shipping UI against the committed images
before every tag.

The picker needs a real person to search for, so a capture of the populated
state needs a fixture user with a recognisable display name. Do not ship a
screenshot showing a real site's user list.
</interfaces>
</context>
