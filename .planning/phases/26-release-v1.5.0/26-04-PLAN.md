**THE STEP THAT IS ALWAYS FORGOTTEN.** The GitHub Release is automatic
(`release.yml` on `push: tags: v*`), but the **SVN deploy is NOT**. A Release
created with `GITHUB_TOKEN` does not emit `release: published`, so `wp-deploy.yml`
never fires on its own. Dispatch it by hand:

    gh workflow run wp-deploy.yml -f tag=v1.5.0

This has been true for v1.3.0, v1.4.0 AND v1.4.1 — three releases, three manual
dispatches. It is not a fluke to be rediscovered a fourth time.

**Verification order matters.** The wp.org API's `version` field lags the SVN
commit by up to ~an hour. SVN is the truth at deploy time: check `trunk`'s
Stable tag and the presence of `tags/1.5.0/`. An unchanged API response is not
evidence of failure.

Plugin Check on the built zip: the `1.3.0` upgrade-notice WARNING is
pre-existing and expected. 0 ERRORS is the bar.
</interfaces>
