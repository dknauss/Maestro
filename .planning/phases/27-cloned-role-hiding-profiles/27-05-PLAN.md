<!-- Contracts the executor builds on. Use directly — no exploration needed. -->

`hidden-users.spec.ts` is the model to follow, including its hard-won mechanics:
- fixture users created by the spec, since running the PHP integration suite
  **reinstalls the shared tests DB and wipes every user but admin**
- sessions created ONCE per file, not per test — per-test logins added enough
  load to start flaking unrelated specs
- the navigation budget comes from `navigationTimeout` in playwright.config.ts

**The load-bearing assertion is the BYSTANDER.** A user outside the profile must
keep every row. Everything else would pass just as happily if the rule had
widened to everyone — that is precisely what the per-user spec's bystander case
exists to catch, and profiles have the same failure mode with a larger blast
radius, since a profile is a group by construction.

**Port note:** if another project holds 8888/8889, use the documented fallback
(dev 8890 / tests 8899) AND pass `WP_ENV_TESTS_PORT=8899` — Playwright reads it
independently of wp-env.
