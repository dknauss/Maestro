**Four lessons this surface has already taught, in order of how much they cost:**

1. **Server, model and client must agree on the axis** or a round-trip save
   silently drops a working rule. `get_menu_model()` must resolve
   `hiddenProfiles` through `resolved_override_list()` — the SAME resolver — and
   `buildConfig()` must emit under the key `Config::sanitize()` accepts.
2. **A gate that is only client-side is not a gate.** If 27-01 decided profile
   authoring needs `list_users` (it names people), enforce it server-side too.
   The v1.5.0 ultrareview found the per-user version of exactly this, and the fix
   then needed three more rounds.
3. **Do not re-inline a tested predicate.** Pure logic goes in
   `maestro-logic.js`; the popover calls it. Both `isChildRoleLockedByParent` and
   the user-axis helpers had to be fixed for this.
4. **Detach-before-outside-click.** `placePopover()`'s handler tests
   `pop.contains( e.target )`; any control that re-renders its own container on
   click must `stopPropagation()` or it tears the popover down. This bit the
   person picker's results AND its chips.

**Also carry forward:**
- Emit ids + display labels together, resolved in ONE batched pass — the person
  picker's model does this and the reasoning holds for profile membership too.
- The marker convention: `.maestro-has-hidden` means "this row has a hide rule of
  its own", which is now ANY of three axes. Seed and toggle sites must agree —
  they have drifted twice.
- REST URLs: choose the separator (`?` vs `&`). `rest_url()` already carries a
  query string on plain permalinks, which 404'd the person picker.
</interfaces>
