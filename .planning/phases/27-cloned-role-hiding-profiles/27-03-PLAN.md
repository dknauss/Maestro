**The reserved slot** — `class-replay.php` ~L510:
```php
// Term 3 — hidden_profiles (cloned-role half of ROLE-02) slots in here,
// resolving profile membership live. Deferred; …
```
Replace the comment with the term. Keep the terms independent — do not fuse them
into one condition; the shape is what made this phase an addition.

**THE ASYMMETRY 27-01 must have already worked out.** Terms 1 and 2 are list
intersects against a property of the current user (`$user->roles`, `$user->ID`).
Term 3 is NOT: `hidden_profiles` holds profile NAMES, and whether the current
user is in a profile requires reading the `profiles` map's assignment list. So
the term is "does any profile named in this item's axis currently contain me".

That is still one seam and one drop path — but it does mean the seam now touches
the profiles map for MEMBERSHIP. That is explicitly allowed by §7 ("consulted only
to know whom a profile currently applies to") and is what makes membership
self-healing. Build the membership index ONCE per request, not per item: the note
calls for "a per-request in-memory index from slug → owning profiles, built once".

**Do not let this become a second resolve path.** The item's axis is still read
through `resolved_override_list( 'hidden_profiles', … )` so it inherits the
qualified-key, schema-v2 and Axis-1/Axis-2 guards. Only membership comes from the
map.

**The fast path must survive.** `is_hidden_for_current_user()` returns before
resolving the current user when NO axis is present. A config with no profiles
must not pay for a membership index.
