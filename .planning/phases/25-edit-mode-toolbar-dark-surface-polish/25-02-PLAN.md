**Do not re-derive the scope.** 25-01 decided it; implement exactly that list. If
a criterion was struck there, it stays struck — reopening it here would defeat
the point of having audited.

**Constraint carried from the original scoping, still binding:** improve rename
commit feedback WITHOUT introducing live as-you-type autosave. The
commit-on-Enter/blur model and the HARD-03 save-race behaviour both depend on it.
`save-race.spec.ts` is the guard; if it fails, the change went too far.

**Testing patterns available on this surface** (established during the v1.5.0
gates — reuse rather than reinvent):
- contrast is computed from the CSS tokens, not eyeballed from a capture
- `@axe-core/playwright` scans a scoped selector; scope it to the TOOLBAR here,
  not the whole admin screen, so pre-existing wp-admin findings do not train
  people to ignore the result
- layout shift is observable by measuring an element's bounding box before and
  after a state change, which is a real assertion rather than a screenshot diff

**Verify across Default / Modern / Midnight admin colour schemes.** Phase 23
spot-checked all three and this toolbar inherits from none of them — it is a
custom-drawn dark surface, so a scheme change must not alter it. That is worth
one assertion rather than an assumption.
